# 평판 모니터

공개 검색 결과와 RSS에서 등록 대상의 부정 표현을 수집하고 검토 기록을 관리하는 로컬 앱입니다.

## 실행

Windows에서는 `start.cmd`를 두 번 클릭합니다. 설치된 사용자 전용 Node.js 런타임을 사용하며 브라우저가 자동으로 열립니다. 기본 주소는 `http://127.0.0.1:4310`입니다. 해당 포트를 다른 프로그램이 사용하면 4311~4349 중 빈 포트를 사용합니다. 종료하려면 실행 창에서 Ctrl+C를 누릅니다.

처음에는 데이터가 없습니다. **키워드 등록**에서 대상 이름·부정 키워드·별칭·제외어를 저장하고 **검색·수집**에서 등록 대상과 매체·기간을 선택해 실행하세요. 체험 데이터는 선택해서 넣을 수 있으며 실제 수집 결과와 구분됩니다.

## 주요 기능

- 등록 관리: 대상 이름·부정 키워드·별칭·제외어·색상·활성화
- 수집 관리: 등록 대상·매체·기간·중복 조건·수집 한도·취소
- 대상 이름 또는 별칭과 부정 키워드의 조합 검색 및 실제 결과 필터링
- 네이버·네이버뉴스·구글·유튜브·틱톡·인스타그램·X·쓰레드 및 네이버 블로그·네이버 카페·다음 카페 검색
- 커뮤니티 분류: 에펨코리아·디시인사이드·뽐뿌·루리웹·클리앙·보배드림·더쿠·인스티즈·네이트판·여성시대·아카라이브
- 수집 결과 기본 필터(부정 + 모든 상태), 본문·제목 내 부정 단어 빨간색 강조, 게시글 링크 점검 및 오류 시 빨간 링크 아이콘 표시
- 수집 결과별 온라인 신고하기(매체별 신고센터 연결)와 신고원고 작성
- 신고원고: 유형별 템플릿 에디터, AI 작성 프롬프트(프롬프트 복사·외부 AI 연결·선택적 API 작성), 증빙 이미지 첨부, 신고 결과(신고예정·신고중·삭제예정·삭제완료) 관리
- 제목·요약 동일 콘텐츠 그룹, URL별 원문 보존, 같은 URL 재조회 횟수·최근 조회 기록
- 공격·비방, 위협, 개인정보 노출, 차별 표현의 검토 후보 표시와 원문 확인 기록
- Google 뉴스 한국어 RSS와 사용자 지정 공개 HTTPS RSS/Atom
- 감정·기간·키워드·출처·태그·메모·우선순위·기한 초과·중복 필터, 정렬과 저장 필터
- 관심 언급, 일괄 처리, 담당자·메모·태그, 대응 기한과 긴급도 관리
- 감정 사전 편집, 수동 수정 및 재분석 시 수동 분류 보호
- 부정 언급 알림과 읽음 처리, 기간별 추이와 키워드별 현황
- 현재 검색 결과 또는 선택 결과의 CSV·인쇄용 HTML 보고서
- 전체 JSON 백업·복원, 보관 기간과 데이터 삭제

HTML 보고서는 브라우저에서 인쇄하거나 PDF로 저장할 수 있습니다. 프로그램이 PDF 파일을 직접 생성하지는 않습니다.

## 등록과 수집

**등록 관리 → 키워드 등록**에서 대상 이름과 부정 키워드(최대 10개), 별칭, 제외어를 저장합니다. 기존 부정어 필드가 없는 등록 데이터에는 불만·환불·불친절을 기본으로 적용하며 수정할 수 있습니다. 과거 수집 자료는 삭제하거나 새 조건으로 재필터링하지 않습니다.

**수집 관리 → 검색·수집**에서는 등록된 활성 대상을 선택합니다. 이름·부정어·제외어는 이 화면에서 다시 입력하지 않으며 서버가 저장된 등록값을 적용합니다. 매체·기간·한도·저장 여부·중복 조건은 수집 화면에서 지정합니다. 등록 화면의 대상별 검색 버튼으로 해당 대상의 수집 화면을 열 수도 있습니다.

대상 이름과 부정 키워드를 각각 결합해 검색하고, 등록 별칭 중 처음 3개도 같은 방식으로 조회합니다. 제목·요약에 대상 이름 또는 별칭이 포함되고 부정 키워드 중 하나 이상이 포함된 결과만 수집하며 제외어가 포함되면 제외합니다. 부정 키워드 일치는 감정 분석·권리침해 후보 판정과 별개이며 위법을 의미하지 않습니다. 매체별 동시 질의는 4개로 제한하고 제한시간 내 완료된 검색만 반영합니다. 같은 URL은 결과 행을 중복 생성하지 않고 조회 횟수·최근 조회를 갱신하며 메모·담당자·검토 기록은 유지합니다. 다른 URL의 동일 콘텐츠는 각각 보존합니다. 자동 저장을 끄면 조회만 하며 조회 횟수도 갱신하지 않습니다.

제목·요약의 대소문자·공백·유니코드 표기를 정규화해 일치하는 글을 중복 그룹으로 표시합니다. 요약이 없으면 제목만으로 다른 URL을 묶지 않습니다. 원문 전체·유사 문장·이미지의 복제를 판정하는 기능은 아닙니다. **중복 콘텐츠만 수집**은 이번 검색 결과 중 같은 제목·요약으로 서로 다른 URL이 2개 이상 발견된 그룹만 저장합니다. 같은 URL의 반복 검색만으로 콘텐츠 중복 그룹을 만들지 않습니다. 이번 조회 범위 밖 자료는 포함하지 않으므로 결과 0건은 중복 글이 없다는 증명이 아닙니다.

**수집 결과**는 기본적으로 **부정 + 모든 상태**로 표시되며 제목·요약 속 부정 단어와 부정어 태그를 빨간색으로 강조합니다. 상단 **링크 점검** 버튼을 누르면 현재 페이지 게시글 URL의 접속 상태를 확인해 오류(404·410·서버 오류·연결 실패) 링크는 제목 옆에 빨간색 끊어진 링크 아이콘으로 표시합니다. 사이트의 봇 차단(403·429 등)은 삭제와 구분해 미확인으로 표시합니다. 중복 필터는 작업 공간 전체에서 제목·요약 중복과 URL 재조회를 구분합니다. 그룹 버튼과 상세 화면에서 같은 그룹의 원문 링크를 확인합니다. 최근 조회는 검색 결과에서의 확인 시각이며 실제 원문 열람 시각은 별도 원문 검토 기록입니다. CSV·HTML에는 감지 부정 키워드·콘텐츠 그룹·URL 수·재조회 정보가 포함됩니다.

자동 수집이 켜져 있으면 등록 키워드의 Google 뉴스 RSS에도 대상·부정어 조건을 적용합니다. 자동 수집은 뉴스·등록 RSS 범위이며 모든 매체 검색을 예약 실행하는 기능은 아닙니다. 개발용 `/api/search`는 기존 자유 질의 계약도 유지하지만 등록 기반 화면은 등록 ID로만 수집합니다.

검색 매체는 포털·뉴스·SNS·카페·블로그와 **커뮤니티 분류**로 나뉘며 분류별 전체 선택을 지원합니다. 네이버뉴스는 네이버 뉴스 API 또는 뉴스 검색 HTML을 사용합니다. X·쓰레드와 커뮤니티 11곳은 공개 검색 색인에서 해당 도메인의 게시글만 수집합니다. 여성시대는 다음 카페(카카오 키 설정 시 API) 범위입니다. 로그인·회원 전용 게시판과 색인되지 않은 글은 수집되지 않으며 결과가 0건일 수 있습니다. 각 매체 결과의 검색 링크로 원본 사이트에서 직접 확인할 수 있습니다.

매체당 최대 10·20·50·100건을 선택합니다. 구글은 공개 뉴스 RSS를 수집합니다. 네이버는 공식 뉴스 API가 설정돼 있으면 API로 조회하고, 미설정 시 공개 검색 HTML과 검색 색인에서 결과를 파싱합니다. 유튜브도 공식 API 또는 공개 검색 페이지의 구조화 데이터를 읽습니다. 틱톡·인스타그램은 공개 검색 색인의 해당 플랫폼 게시물 URL·제목·요약을 수집합니다. 검색엔진이 다른 매체를 반환하면 도메인 검증으로 제외합니다.

확인된 게시일은 한국시간의 시작일 00:00부터 종료일 마지막 시각까지 검사합니다. 게시일 미확인 데이터는 '게시일 미확인'과 '기간 검증 안 됨'으로 표시하며 DB의 대체 시각은 수집일입니다. **게시일 확인 결과만** 옵션을 켜면 미확인 결과를 제외합니다. RSS·공개 HTML·공식 API·색인 수집 방식을 결과에 구분하고 신규·중복·보관기간 제외 건수를 표시합니다. 부분 실패는 다른 매체의 성공 결과를 막지 않으며 수집 이력에 기록합니다. 취소하면 저장 전에 중단합니다.

크롤링은 공개 검색 결과의 제목·URL·요약·제공된 게시일을 대상으로 하며 원문 전체·동영상·이미지 다운로드는 아닙니다. 미색인·비공개·로그인 전용 게시물이나 모든 과거 검색 결과를 보장하지 않습니다. 사이트 차단·CAPTCHA·로그인을 우회하지 않습니다. 틱톡 연구 검색 API와 인스타그램 공개 콘텐츠 API의 전체 연결은 구현하지 않았으며 승인된 계정·앱 권한이 필요합니다. 공개 색인 결과가 없거나 차단되면 그 상태를 표시합니다.

### 공식 API 연결

선택적으로 프로젝트 루트의 `.env` 파일에 `.env.example`의 항목을 설정하고 앱을 다시 시작합니다. 네이버는 `NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET`, 유튜브는 `YOUTUBE_API_KEY`, 다음 카페는 카카오 앱의 `KAKAO_REST_API_KEY`를 사용합니다. 키는 서버 환경에서만 사용하며 DB·JSON 백업·브라우저 응답에 포함하지 않습니다. 네이버와 다음 카페는 검색어별 최신 최대 300건 범위에서 기간을 검사하며, 유튜브는 기간 조건과 다음 페이지를 사용해 최대 100건 조회합니다. 계정 발급·API 활성화·사용량 제한과 비용은 해당 매체 정책을 따릅니다. 키를 채팅으로 전달하지 마세요.

### 카페·블로그 원문 검토

**검색·수집** 화면은 기본적으로 네이버 블로그·네이버 카페·다음 카페를 선택합니다. 대상과 부정어는 **키워드 등록**에서 설정하고 매체 체크박스로 뉴스·SNS를 추가할 수 있습니다. 제외어가 제목·요약에 포함된 결과는 저장하지 않으며 원문 전체에서의 제외 여부는 보장하지 않습니다.

네이버 공식 블로그 검색(`blog.json`)과 공개 카페글 검색(`cafearticle.json`), 카카오 다음 카페 검색(`/v2/search/cafe`)을 연결했습니다. 네이버 키가 없으면 공개 검색 HTML과 색인, 다음 카페 키가 없으면 공개 색인을 사용합니다. 전용 검색은 해당 매체의 게시글 URL만 허용하며 카페 홈·다른 블로그 서비스 등은 제외합니다. 네이버 카페 API는 게시일을 제공하지 않으므로 **게시일 확인 결과만**을 켜면 이 API 결과는 제외됩니다. 알려진 게시일이 없는 결과는 기간 검증이 되지 않은 상태로 표시합니다. 과거 기간을 지정해도 최신 조회 한도 밖 자료까지 모두 수집하지 않습니다.

제목·요약의 고정 표현 사전으로 **검토 후보**를 표시합니다. 부정 키워드 일치와 감정 점수와는 별개이며 예방 안내·인용·반어법도 후보가 될 수 있습니다. 후보가 없다고 문제가 없다는 뜻은 아니며 비방·인권침해·위법 여부를 자동 판정하지 않습니다. 등록 부정 키워드는 수집 조건이지 권리침해 후보 사전을 바꾸는 설정은 아닙니다. 후보 근거에서 인식한 휴대전화·식별번호는 가리지만 모든 개인정보를 탐지·가리는 기능은 아닙니다. 저장된 검색 요약과 담당자 인용문은 자동 익명화하지 않습니다.

수집 결과의 **원문 검토 필터**에서 후보를 찾고 상세 화면의 원문 링크로 실제 맥락을 확인합니다. 원문 검토 상태는 미검토·원문 검토 중·원문 확인·대상 아님으로 구분합니다. 인용문, 맥락·검토 사유, 확인자, 확인 시각을 기록할 수 있습니다. **원문 확인** 저장에는 인용문·확인자·확인 시각이 필요하며 시각을 직접 기록하지 않으면 저장 시각을 기록합니다. 원문 확인은 침해 확정이 아닙니다. 같은 URL을 재수집해도 담당자 기록은 유지됩니다.

선택·필터 결과의 CSV 또는 HTML 보고서에는 URL, 게시일 확인 여부, 수집일, 후보 근거, 담당자 인용문·맥락·확인자가 포함됩니다. 이는 검토 기록이며 원본의 변경 방지·진본 인증·법적 증거 적격성을 보장하지 않습니다. 원문 전체·자동 스크린샷 수집, 신고의 자동 제출, 작성자 추적, 회원 전용 접근·차단 우회는 포함하지 않습니다. 개인정보가 든 인용문과 보고서는 필요한 범위에서만 보관·공유하세요. 저장된 기록에도 보관 기간과 최대 언급 수 제한이 적용됩니다.

## 신고 관리

**수집 결과**의 각 글과 상세 화면에서 **온라인 신고하기**를 누르면 해당 매체의 신고·권리침해 접수 페이지가 열립니다. 전용 신고 페이지가 없는 매체는 사이트 첫 화면 또는 방송통신심의위원회 페이지로 연결됩니다. 신고 접수는 각 사이트에서 직접 진행하며 앱이 자동으로 제출하지 않습니다.

**신고원고 작성**을 누르면 **신고 관리 → 신고원고**에서 대상 URL·제목·감지 키워드·인용문을 채운 원고가 열립니다. 신고 유형(권리침해·명예훼손, 허위사실·업무방해, 개인정보 노출, 모욕·비방)을 바꾸면 템플릿이 다시 작성되고, 문구 빠른 삽입·본문 복사를 사용할 수 있습니다. **AI 작성 프롬프트** 영역에서는 신고 정보와 추가 지시사항을 결합한 프롬프트를 자동 생성해 복사하거나 ChatGPT·Claude를 열어 작성 결과를 에디터에 붙여넣을 수 있으며, `.env`에 `OPENAI_API_KEY`가 설정된 로컬 서버에서는 **AI로 바로 작성** 버튼으로 원고 초안을 생성할 수 있습니다. 증빙 이미지는 PNG·JPG·WEBP·GIF로 원고당 최대 5장, 장당 1MB까지 첨부합니다.

신고 결과는 신고예정·신고중·삭제예정·삭제완료로 관리하며 연결된 수집 결과의 신고 상태와 함께 바뀝니다. 수집 결과는 **신고 결과 필터**로 모아볼 수 있고 CSV·HTML 보고서에 신고 상태가 포함됩니다. 신고 원고와 첨부 이미지는 작업 공간에 저장되고 JSON 백업에 포함되므로 개인정보가 담긴 캡처는 필요한 범위에서만 보관하세요. 템플릿 문구는 작성 보조용이며 법률 자문을 대신하지 않습니다.

## 웹·모바일 페이지(GitHub Pages)

`.github/workflows/pages.yml`이 `main` 브랜치에 올라가면 화면을 빌드해 GitHub Pages에 배포합니다. 저장소의 **Settings → Pages → Source**를 **GitHub Actions**로 설정하면 `https://<계정>.github.io/<저장소>/`로 접속합니다.

GitHub Pages에는 서버가 없으므로 화면이 브라우저 단독 모드로 동작합니다. 키워드 등록, 수집 결과 관리, 신고원고 작성·이미지 첨부·상태 관리, 온라인 신고 링크, CSV·보고서·백업 내려받기는 작동합니다. 다른 사이트 자동 수집은 브라우저 보안 제약으로 동작하지 않으며, 검색·수집 화면은 매체별 검색 링크만 제공합니다. 데이터는 접속한 기기의 브라우저 저장소에만 저장되어 기기 간 공유되지 않으며 브라우저 데이터를 지우면 사라집니다. 기기를 옮길 때는 설정의 백업·복원을 사용하세요. 자동 수집이 필요하면 PC의 로컬 서버(`start.cmd`)를 사용합니다.

## 데이터와 제한

데이터는 `data/reputation.sqlite`에 저장됩니다. 다른 PC로 옮길 때는 설정에서 JSON 백업을 내려받고 복원하세요. 복원은 기존 작업 공간을 대체하며 자동 수집은 꺼집니다. 보관 기간을 줄이면 오래된 언급이 삭제됩니다.

키워드는 30개, 사용자 RSS는 50개, 언급은 최대 20,000개, 저장 필터는 30개, 신고 원고는 500개까지 유지합니다. 각 피드에서 한 번에 최대 200개를 읽습니다. RSS 제공 범위 밖의 과거 자료나 모든 검색 결과를 보장하지 않습니다.

자동 수집은 프로그램과 PC가 켜져 있을 때만 작동합니다. 알림은 앱 내부 알림이며 이메일·문자·메신저 발송은 포함하지 않습니다. 감정 분석은 표현 사전 기반이라 풍자, 문맥, 부정문을 정확히 판단하지 못할 수 있습니다. 중요한 대응은 원문을 확인하세요.

로그인 필요한 SNS·카페·리뷰 사이트의 전체 수집은 포함하지 않습니다. 사용자 RSS는 HTTPS 공개 주소만 허용하며 내부망·로컬 주소와 DNS 재바인딩을 차단합니다. 인증이 없는 로컬 전용 앱이므로 서버를 외부에 공개하지 마세요.

## 개발 및 검증

Node.js 22.13 이상과 npm이 필요합니다. Windows PowerShell에서는 실행 정책에 따라 `npm` 대신 `npm.cmd`를 사용합니다.

```powershell
npm.cmd install
npm.cmd run dev
npm.cmd run build
npm.cmd test
npx.cmd playwright install chromium
npm.cmd run test:e2e
npm.cmd run lint
```

브라우저 테스트는 4325 포트와 `.test-data/reputation.sqlite`를 사용해 사용자 DB와 분리됩니다. 테스트 전에 최신 화면을 빌드하세요. 테스트 결과는 `test-results/`에 저장됩니다.

React·TypeScript·Vite 화면, Express API, Node.js SQLite로 구성됩니다. 서버는 기본적으로 127.0.0.1에만 연결합니다. 개발 API 포트는 4310, Vite 화면 포트는 보통 5173입니다.
